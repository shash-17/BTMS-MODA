EXHAUSTIVE PROJECT & TESTING REPORT: BATTERY THERMAL MANAGEMENT SYSTEM (BTMS)
================================================================================

1. OBJECTIVE OF THE APPLICATION
--------------------------------------------------------------------------------
The primary objective of the Battery Thermal Management System (BTMS) is to prevent 
catastrophic thermal runaway in high-density lithium-ion battery packs. Traditional 
temperature sensors trigger alarms only *after* critical heat thresholds are breached. 
The BTMS solves this by acting preemptively. Using an Unsupervised Machine Learning 
model (Isolation Forest), it continuously analyzes 8-dimensional telemetry across 
individual cells to predict chemical degradation *before* heat spikes occur. When an 
anomaly is detected, the system leverages a Computational Fluid Dynamics (CFD) physics 
engine to actively dose Aluminum Oxide (Al2O3) nanofluid and dynamically adjust coolant 
flow velocities, mathematically suppressing the hotspot while minimizing the auxiliary 
parasitic load on coolant pumps.


2. SYSTEM FEATURES
--------------------------------------------------------------------------------
1. Real-Time 3D Digital Twin: Interactive WebGL (Three.js) visualization of the 
   battery pack (10x 21700 cells) displaying dynamic thermal gradients.
2. AI Anomaly Detection: Isolation Forest machine learning model generating anomaly 
   confidence scores (Normal, Warning, Critical) based on voltage/current sags.
3. CFD Nanofluid Optimization: Active dynamic cooling control that computes flow 
   velocity, Reynolds numbers, and Nusselt numbers in real-time.
4. Online Background Retraining: The AI model automatically refits itself every 
   50 seconds on a rolling buffer of 1000 live samples to adapt to battery aging.
5. Role-Based Access Control (RBAC): Secured operator (read-only) and admin (override) 
   portals backed by JWT Bearer tokens and bcrypt.
6. Microservice Health Monitor: Real-time latency tracking and uptime badges for all 
   backend microservices (FastAPI, Flask, Redis).


3. FUNCTIONAL REQUIREMENTS (FRs)
--------------------------------------------------------------------------------
- FR-01 (Ingestion): The system must ingest 10-cell telemetry arrays (V, I, Temp, SoC) 
  at exactly 1 Hz (1 update per second) via a REST POST API.
- FR-02 (Processing): The AI Engine must dequeue telemetry from Redis, normalize the 
  temperatures, and assign an anomaly severity score within the same tick.
- FR-03 (Physics Calculation): Based on the AI severity, the system must calculate 
  the target Reynolds Number (400-700) and Nanofluid concentration (0.5% - 3.0%).
- FR-04 (Authentication): The system must support Operator and Admin registration, 
  and reject unauthenticated users attempting to access telemetry via HTTP 401.
- FR-05 (Visualization): The React frontend must fetch `/telemetry/latest` and update 
  the 3D canvas color shaders dynamically based on cell surface temperatures.


4. NON-FUNCTIONAL REQUIREMENTS (NFRs)
--------------------------------------------------------------------------------
- NFR-01 (Latency): The `cfd_optimise` physics function must execute in < 1.0 ms. 
  The `/telemetry/latest` API must respond in < 50 ms to ensure real-time UI feel.
- NFR-02 (Scalability): The architecture must be decoupled. Ingestion spikes must 
  be buffered in Redis (LPUSH) so the AI Engine (RPOP) is never overwhelmed.
- NFR-03 (Security): Passwords must be hashed using bcrypt (cost=12). JWTs must use 
  HMAC-SHA256. Database inputs must be strictly parameterized to prevent SQLi.
- NFR-04 (Reliability/Availability): The backend must gracefully handle simulated 
  failures. Mutation testing score must achieve a 100% kill rate on critical targets 
  to prove fault tolerance.


5. SOFTWARE TESTING METHODOLOGY & TECHNIQUES USED
--------------------------------------------------------------------------------
The BTMS utilizes an aggressive, multi-layered "defense-in-depth" testing methodology. 

Techniques Used:
- Boundary Value Analysis (BVA): Used heavily in mutation testing and unit tests 
  to ensure temperatures > 45.0C strictly trigger Critical states.
- Equivalence Partitioning: Used in Data-Driven Testing (DDT) to group temperature 
  bands (15-40C Normal, 40-45C Warning, >45C Critical) for parametric pytest sweeps.
- Keyword-Driven Testing (KDT): Abstract action scripts interpreting keywords to 
  simulate UI business logic.
- Dynamic Application Security Testing (DAST): Wapiti scans against live endpoints.
- Abstract Syntax Tree (AST) Mutation: Mutmut aggressively injects code flaws (e.g., 
  flipping logical operators, mutating math constants) to evaluate test suite quality.
- Micro-Benchmarking: Timeit loops to guarantee execution latency SLAs.


6. DETAILED TEST CASE BREAKDOWN (Derived from /tests directory)
--------------------------------------------------------------------------------
Below is a highly detailed enumeration of the test cases explicitly coded in the project.

A. UNIT TESTING (tests/unit/ - 30 Tests)
White-box tests asserting algorithmic exactness.
- test_cfd_physics.py
  - `test_nanofluid_properties_base`: Asserts density/viscosity at 0.5% Al2O3.
  - `test_nanofluid_properties_max`: Asserts density/viscosity at 3.0% Al2O3.
  - `test_compute_flow_velocity_validity`: Validates v = (Re*μ)/(ρ*Dh).
  - `test_compute_nusselt_graetz`: Validates Graetz-Dittus-Boelter equations.
  - `test_cfd_optimise_normal_state`: Asserts normal ml_severity yields lowest pump speed.
  - `test_cfd_optimise_warning_state`: Asserts warning ml_severity raises Re by 100.
  - `test_cfd_optimise_critical_state`: Asserts critical ml_severity maximizes pump/dosing.
  - `test_cfd_optimise_hardware_spike`: Asserts T>45C strictly overrides ML to Critical.

B. FUNCTIONAL TESTING (tests/functional/ - 24 Tests)
Black-box API integration using FastAPI TestClient.
- test_auth_api.py
  - `test_register_success`: Validates HTTP 200 and SQLite insertion.
  - `test_register_duplicate_username`: Validates HTTP 409 Conflict.
  - `test_login_success`: Validates HTTP 200 and issues valid JWT.
  - `test_login_invalid_password`: Validates HTTP 401 Unauthorized.
  - `test_get_me_with_valid_token`: Validates JWT parsing and identity extraction.
  - `test_get_me_with_no_token`: Validates HTTP 403 Forbidden.
- test_dev_server_api.py
  - `test_health_check`: Asserts `/health` returns status "healthy".
  - `test_telemetry_latest_schema`: Validates JSON schema of returned battery state.
  - `test_recommendations_endpoint`: Asserts cooling recommendations are present.

C. SECURITY TESTING (tests/security/ - 31 Tests)
Offensive penetration tests.
- test_auth_security.py (Custom Python Pytest Attacks)
  - `test_sql_injection_in_login_returns_401_not_200`: Injects "' OR '1'='1" into username.
  - `test_sql_injection_in_register_username_rejected`: Injects "'; DROP TABLE users--".
  - `test_jwt_tampering_rejected`: Modifies header/payload signature and asserts HTTP 401.
  - `test_jwt_none_algorithm_rejected`: Attempts "alg": "none" bypass attack.
  - `test_jwt_expired_token`: Asserts tokens past `exp` claim are firmly rejected.
  - `test_xss_payload_in_username`: Injects `<script>alert(1)</script>` into registration.
- test_wapiti_scan.py (DAST)
  - `test_cors_wildcard_is_restricted_appropriately`: Audits allowed origins.
  - `test_https_not_enforced_warning`: Audits TLS/SSL requirements.
  - `test_server_header_disclosure`: Flags Uvicorn versions in HTTP Headers.

D. PERFORMANCE & LOAD TESTING (tests/performance/ - 16 Tests)
- test_performance.py (Microbenchmarks)
  - `test_cfd_optimise_execution_time_under_1ms`: Timeit loop asserting t < 0.001s.
  - `test_auth_login_latency_under_500ms`: Asserts bcrypt hashing bottleneck < 0.5s.
  - `test_telemetry_fetch_latency_under_50ms`: Asserts API read speeds.
- locustfile.py (Distributed Load Testing)
  - `SimulateOperator`: Spawns users that GET `/telemetry/latest` every 1 second.
  - `SimulateAdmin`: Spawns users that authenticate and poll `/health`.

E. MUTATION TESTING (tests/mutation/ - 49 Tests)
Tests proving the tests work by intentionally breaking code.
- test_mutation_targets.py
  - `test_cfd_spike_boundary_exact_45`: Mutmut changes `>` to `>=`. The test must fail.
  - `test_cfd_spike_boundary_45_1`: Mutmut changes `45` to `46`. The test must fail.
  - `test_nusselt_math_inversion`: Mutmut changes `+` to `-` in the Graetz equation.
  - `test_nanofluid_viscosity_exponential`: Mutmut breaks `math.exp(2.5 * phi)`.

G. KEYWORD-DRIVEN TESTING (tests/keyword_driven/ - 25 Tests)

H. SYNTHETIC DATA VALIDATIONS (tests/synthetic/ - 210 Tests)
