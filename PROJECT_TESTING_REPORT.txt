================================================================================
PROJECT REPORT: BATTERY THERMAL MANAGEMENT SYSTEM (BTMS)
================================================================================

1. DEVELOP A SAMPLE WEB/MOBILE APPLICATION
--------------------------------------------------------------------------------
The selected application developed is the "Battery Thermal Management System 
(BTMS) Digital Twin." It is an enterprise-grade web application built using a 
microservices architecture:
- Frontend: React 18, Three.js (WebGL), and Vite.
- Backend: FastAPI (AI & Physics Engine), Flask (Ingestion API).
- Broker: Apache Kafka topics.
- Database: SQLite3 (Authentication/RBAC).
The application monitors, simulates, and optimizes the thermal performance of 
lithium-ion battery packs using real-time AI and Computational Fluid Dynamics.


2. DESIGN SOFTWARE TESTING METHODOLOGY IN DETAIL
--------------------------------------------------------------------------------
The testing methodology employs an aggressive, 8-layer "defense-in-depth" QA 
strategy designed for mission-critical software:

A. Unit Testing: Mathematical validation of core functions (CFD formulas, AI scoring) 
   in isolation to guarantee deterministic behavior.
B. Functional Testing: Black-box integration testing of REST API endpoints using 
   test clients to validate request/response contracts and data schemas.
C. Security Testing: Offensive testing approach simulating malicious actors (SQLi, 
   XSS, JWT tampering) against exposed endpoints.
D. Performance Testing: Benchmarking critical path latency and simulating massive 
   concurrent user load.
E. Mutation Testing: Injecting deliberate bugs (mutants) into the source code to 
   prove the strictness and quality of the test suite itself.
F. Data-Driven Testing (DDT): Parametric testing across massive matrices of inputs.
G. Keyword-Driven Testing (KDT): Abstract action tables simulating business flows.
H. Synthetic Testing: Generating massive datasets of pseudo-telemetry for edge-cases.


3. EXPLORE OPEN SOURCE SOFTWARE TESTING TOOLS FOR WEB APPLICATIONS
--------------------------------------------------------------------------------
The following open-source tools were explored and selected for this project:
- Pytest: A mature, full-featured Python testing framework.
- Mutmut: An advanced mutation testing system for Python.
- Locust: An open-source, scalable load testing tool written in Python.
- Wapiti: A dynamic web application vulnerability scanner (DAST).


4. DOCUMENT THE FUNCTIONALITY OF TESTING TOOLS WITH ITS FEATURES
--------------------------------------------------------------------------------
- Pytest: 
  Features include rich assertions, auto-discovery of tests (`test_*.py`), 
  dependency injection via fixtures, and `@pytest.mark.parametrize` for 
  effortless Data-Driven Testing (DDT).
- Mutmut: 
  Features include Abstract Syntax Tree (AST) parsing to flip operators 
  (e.g., `>` to `<`), modify constants, and ensure tests fail when code breaks 
  (calculates a "kill rate").
- Locust: 
  Features include defining user behavior via Python scripts, simulating 
  thousands of concurrent users using gevent (event-loop), and providing 
  real-time web-based UI reporting for requests per second (RPS) and p99 latency.
- Wapiti:
  Features include crawling web pages, injecting payloads to find SQLi, XSS, 
  CRLF injection, and checking for misconfigurations (e.g., wildcard CORS, 
  missing HTTP headers).


5. DOCUMENT SAMPLE APPLICATION FEATURES
--------------------------------------------------------------------------------
- Real-Time 3D Digital Twin: Interactive WebGL visualization of the battery pack 
  displaying dynamic thermal gradients (color-mapped from green to red).
- AI Anomaly Detection: An Unsupervised Isolation Forest model that evaluates an 
  8-dimensional feature vector per cell to predict thermal runaway before it occurs.
- CFD Nanofluid Optimization: Automatically calculates and adjusts coolant flow 
  velocity and nanoparticle (Al2O3) concentration to suppress localized hotspots.
- Role-Based Access Control (RBAC): Secure login system separating view-only 
  Operators from Admin users who can override physics setpoints.
- Microservice Health Monitor: Visual badges tracking the live latency and uptime 
  status of the Auth, Dev, and Dashboard services.


6. CREATE TEST CASES AND TEST SCRIPTS
--------------------------------------------------------------------------------
Hundreds of test scripts were created. Key representative test cases include:

Test Case 1: `test_cfd_severity_logic` (Unit)
- Objective: Ensure CFD engine correctly raises coolant flow when AI detects anomaly.
- Script: Injects a simulated "critical" anomaly flag and asserts `re_target` 
  and `concentration_key` maximize.

Test Case 2: `test_sql_injection_in_login` (Security)
- Objective: Prevent unauthorized DB access via payload injection.
- Script: Fires `{"username": "' OR '1'='1"}` at `/auth/login`. Asserts response 
  is strictly 401 Unauthorized, never 200 OK.

Test Case 3: `test_cfd_optimise_execution_time` (Performance)
- Objective: Guarantee sub-millisecond AI/Physics calculation speed.
- Script: Uses the `timeit` module to execute `cfd_optimise` 1000 times, 
  asserting the average execution time is < 0.001 seconds.

Test Case 4: `test_mutation_targets` (Mutation)
- Objective: Verify edge-case thresholds trigger failures if mutated.
- Script: Asserts `T > TEMP_CRITICAL` handles boundary inputs properly, killing 
  any mutmut modification that alters the mathematical condition.
